ManyChat → Dashboard Setup

正式 publish 版本会用这个方式收集资料：ManyChat account → External Request / API token → hosted dashboard → database → report。这样 RUN 不需要再靠 Codex 开 Chrome 扫 Inbox。

← 回 Dashboard

每个用户需要做什么

1

在 Dashboard 里建立自己的 ManyChat Account，复制专属 Event URL 和 Event Key。

2

在 ManyChat Flow 加 External Request，把 PM、Pending、After Payment、Tag、真实对话关键点送到 Dashboard。

3

Dashboard 会把事件存进 database。用户点 RUN 时，只是从 database 重新生成 report。

Dashboard 会自动统计

PM 人数 有互动 Pending After Payment 漏回 Collagen Drinks Free Testing Don't Disturb 未下单卡点

重点：数字用事件算，AI 只需要做最后的白话总结或卡点归类，usage 会少很多。

External Request URL 格式

POST https://YOUR-DASHBOARD-DOMAIN/api/manychat-event?account=ACCOUNT_ID&key=EVENT_KEY

本机测试可以用：

POST http://127.0.0.1:4173/api/manychat-event?account=fb108701968299986&key=YOUR_EVENT_KEY

Basic Body template

{
  "account": "fb108701968299986",
  "event_type": "customer_message",
  "occurred_at": "{{now}}",
  "contact": {Full Contact Data},
  "text": "{{last_text_input}}",
  "source": "flow_or_keyword_name",
  "tags": ["{{tag.name}}"]
}

真实输入 / Keyword 后面用

放在顾客有打字、keyword 触发、user input 收到答案后的下一步。Button / quick reply 不要用这个当互动。source 写前一个 flow/step 名称，Dashboard 会用它辅助判断顾客卡点。

{
  "event_type": "customer_message",
  "account": "ACCOUNT_ID",
  "contact": {Full Contact Data},
  "text": "{{last_text_input}}",
  "source": "keyword_or_user_input",
  "blocker": ""
}

AI / 人工判断卡点后面用

放在 AI step、条件分支或你已经判断顾客卡点的位置，直接送分类给 Dashboard。

{
  "event_type": "customer_message",
  "account": "ACCOUNT_ID",
  "contact": {Full Contact Data},
  "text": "{{last_text_input}}",
  "source": "ai_or_manual_category",
  "blocker": "price_concern"
}

建议固定卡点分类

price_concern need_consider proof_question shipping_question payment_question product_question no_clear_blocker

比较稳的规则：顾客只是点“想了解关节/皮肤/胶原饮”等入口，不算有互动；顾客自己打字、语音转文字、问价钱、效果、付款、运输、适合谁，才送 customer_message。若顾客先打字再点 button，仍然算真实互动。

建议建立的事件

pm_subscribed：新顾客 subscribed / PM 进来时送出。
customer_message：顾客有真实输入或你在 Flow 判断到 intent/blocker 时送出。Button / quick reply 不要送成真实互动。
page_reply：Page / admin 回复后送出，用来判断漏回。
pending_added：顾客被加 Pending Tag 时送出。
after_payment：After Payment / AO Flow 触发时送出。
tag_added：RM4.90drinks、Free Testing、Don't Disturb 等重要 tag 触发时送出。

Broadcast Campaign Tracking

每一场 Broadcast 的 Campaign 不需要在 Dashboard 手动新增。ManyChat 在每一项 WhatsApp Broadcast 发出/进入 Broadcast Flow 时，先送 Campaign 事件。Lead / Order 只会归到已存在的 Campaign；如果 Campaign 还没创建，会返回错误提醒先送 Campaign。

你需要在每一场 Broadcast Flow 开头 Set User Field：last_broadcast_campaign。值可以像：2026-08-04_Merdeka_LastCall。顾客回应内容另外放在 last_broadcast_respon。

ScaleStory 990 · fb108701968299986 ScaleStory 968 · fb111840620574302 ScaleStory 997 SG · fb701760706347255

Campaign External Request

POST https://YOUR-DASHBOARD-DOMAIN/api/manychat/broadcast-campaign?key=EVENT_KEY
{
  "manychat_page_id": "fb111840620574302",
  "campaign_name": "{{last_broadcast_campaign}}",
  "broadcast_date": "{{now}}",
  "total_spending": 0
}

Lead External Request

POST https://YOUR-DASHBOARD-DOMAIN/api/manychat/broadcast-lead?key=EVENT_KEY
{
  "manychat_page_id": "fb111840620574302",
  "campaign_name": "{{last_broadcast_campaign}}",
  "manychat_contact_id": "{{contact.id}}",
  "customer_name": "{{first_name}} {{last_name}}",
  "lead_date": "{{now}}",
  "response_text": "{{last_broadcast_respon}}"
}

Order External Request

POST https://YOUR-DASHBOARD-DOMAIN/api/manychat/broadcast-order?key=EVENT_KEY
{
  "manychat_page_id": "fb111840620574302",
  "campaign_name": "{{last_broadcast_campaign}}",
  "order_id": "{{contact.id}}-{{last_broadcast_campaign}}",
  "manychat_contact_id": "{{contact.id}}",
  "customer_name": "{{first_name}} {{last_name}}",
  "order_amount": 779,
  "order_date": "{{now}}"
}

所有金额默认是 MYR。不要传 currency、不要传 SGD、不要做汇率转换。Total Spending 如果当下还不知道，可以先传 0；ROAS 会显示 “—”，不会出现 NaN 或 Infinity。
